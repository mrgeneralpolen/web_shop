# Интернет-магазин «Онлайн-Трейд»

Полный исходный код интернет-магазина с модулем авторизации:
каталог из 12 товаров, корзина, оформление заказов, регистрация и вход,
личный кабинет с историей заказов.

## Стек

- **Фронтенд:** React 18 + Vite + TypeScript
- **Бэкенд:** Python 3.12 + FastAPI + SQLAlchemy
- **БД:** SQLite по умолчанию (файл `backend/shop.db`, создаётся сам при запуске),
  схема для PostgreSQL 16 — в `db/schema_postgres.sql`

## Запуск бэкенда

```bash
cd backend
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r ../requirements.txt
uvicorn app.main:app --reload    # http://localhost:8000
```

При первом запуске создаются таблицы и выполняется seed:
12 товаров, роли `admin` / `user`, демо-аккаунт (см. ниже).
Документация API: http://localhost:8000/docs

Переменная окружения `DATABASE_URL` (по умолчанию `sqlite:///./shop.db`)
позволяет указать другую базу, например PostgreSQL:
`DATABASE_URL=postgresql+psycopg2://user:pass@localhost:5432/shop`
(для PostgreSQL установите `psycopg2-binary` и примените
`db/schema_postgres.sql`).

## Деплой бэкенда (Railway / Docker)

В репозитории есть `Dockerfile` — он сам ставит зависимости и запускает
бэкенд на порту из `$PORT`. На Railway достаточно выбрать этот репозиторий:
платформа найдёт `Dockerfile` и соберёт контейнер.

Если деплоишь без Docker (например, Railway + Nixpacks): поставь корневую
папку сервиса `backend` и стартовую команду
`uvicorn app.main:app --host 0.0.0.0 --port $PORT` — рабочая папка должна
быть `backend/`, потому что код лежит в пакете `app/` внутри неё.

Если файлы пакета `app` лежат плоско в корне (рядом с `main.py`, без папки
`app/`) — тоже запустится: импорты в `main.py`, `auth.py`, `models.py`,
`seed.py` и `database.py` сами переключаются на плоскую раскладку, а команда
тогда `uvicorn main:app --host 0.0.0.0 --port $PORT`.

Переменная `DATABASE_URL` по умолчанию `sqlite:///./shop.db` — в контейнере
файл базы живёт рядом с бэкендом; для постоянного хранения подключи Volume
или PostgreSQL (см. `db/schema_postgres.sql`).

**Прод на Railway — один сервис, один адрес.** Dockerfile в корне
репозитория собирает фронт и бэкенд в один образ: бэкенд раздаёт и API,
и собранный фронт с того же адреса. Деплой: один сервис из репозитория,
Dockerfile определяется сам. Открыл ссылку сервиса — и сразу магазин.
Проверка, что сервис жив: `https://<домен>/api/health` —
должен ответить `{"status":"ok",...}`. `CORS_ORIGINS` больше не нужен:
фронт и API на одном origin. Живой адрес бэкенда сейчас:
`https://webshop-production-6dbd19ff.up.railway.app`.

## Просмотрщик базы данных

В подвале сайта — ссылка «Схема базы данных»: встроенный просмотрщик
(как в DBeaver). Вкладка «Таблицы» — список всех 15 таблиц с числом строк
и столбцами (тип, NULL, PK/FK/UNIQUE). Вкладка «ERD-диаграмма» —
диаграмма связей между таблицами. Данные берутся из `GET /api/db/schema`,
который строится из моделей бэкенда, поэтому схема всегда соответствует
реальной базе. Хеши и секреты в просмотрщик не попадают — только структура.

## Архитектура в 10 строках

1. Браузер (React) ходит только в REST API бэкенда (`/api/*`).
2. FastAPI проверяет `Authorization: Bearer <токен>` на защищённых ручках.
3. Токен доступа — UUID сессии из `sessions.session_id`, живёт 15 минут.
4. Токен обновления (30 дней) хранится только как SHA-256-хеш и позволяет
   получить новый токен доступа.
5. Пароль: SHA-256(соль + пароль), соль и хеш — одной строкой
   `salt_hex$hash_hex` в `users.password_hash`, проверка — сравнением хешей.
6. Корзина привязана к `user_id`; гость оформляет заказ только после входа.
7. Заказ создаётся одной транзакцией: списание остатков, очистка корзины.
8. Все события входа/заказа пишутся в `audit_log` и `login_attempts`;
   5 неудачных входов подряд блокируют учётную запись на 15 минут,
   а при смене пароля завершаются все сессии пользователя.
9. Роли и права — в `roles` / `permissions`, связь — через `user_roles`.
10. Схема БД одна для SQLite и PostgreSQL (типы совместимы);
    `db/schema_postgres.sql` повторяет словарь данных отчёта один в один.
